## Alternatives Considered

- **Annotated SemVer tag plus existing GitHub workflow and native runtime CLIs (selected):** SemVer assigns backward-compatible functionality to a minor release, so issue #9 moves beads-lifecycle from 1.5.2 to 1.6.0 and the independently versioned capability from 0.6.2 to 0.7.0; the repository's current [tag-triggered release workflow at the verified source SHA](https://github.com/davdittrich/gsd-beads/blob/9ccd20271ae60d13d13ab22d5204136843085a59/.github/workflows/release.yml) (2026) already packages the allowlisted marketplace payload. Decided by: performance first, because the immutable tag prevents unrelated commits from invalidating the Codex cache; simplicity/LOC next, because no new release machinery exists.
- **Track `main` in Codex and run a marketplace-wide upgrade:** This avoids changing the ref on each release, but the repository's [issue #8 cache invalidation analysis](https://github.com/davdittrich/gsd-beads/issues/8) (2026) and the upstream [Codex issue #31383](https://github.com/openai/codex/issues/31383) (2026) record that any new tracked commit can force reinstall configured plugin caches. Decided by: performance; rejected because it can rewrite sibling plugin state and destabilize live sessions.
- **Copy the published plugin and capability trees into runtime caches manually:** This could produce matching bytes once, but bypasses each runtime's installation registry and the capability hook's native writer/ownership checks described in the source-pinned [capability projection contract](https://github.com/davdittrich/gsd-beads/blob/9ccd20271ae60d13d13ab22d5204136843085a59/README.md#capability-projection-updates) (2026). Decided by: ecosystem support and maintenance overhead; rejected because copied bytes are not provider-confirmed installations and can cross runtime ownership boundaries.
