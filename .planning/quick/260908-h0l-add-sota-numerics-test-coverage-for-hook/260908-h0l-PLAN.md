## Alternatives Considered

Every mechanism this plan needs already ships in the target repo's toolchain
(bash, python3 stdlib `unittest`, `find`, `sha256sum`), so the open choices are
placement and scope, not dependencies. No new library is introduced, and none was
a candidate.

### Internal design alternatives

- **Where the SubagentStart wiring test lives**: a new `tests/test-hooks-manifest.sh`
  plus a fifth CI step, versus a case appended to `tests/test-session-start.sh`.
  Chosen: the existing suite. It already targets `session-start.sh`, already
  requires python3, and already runs in CI, so the new file would add a CI leg
  and a second harness for assertions whose whole point is that the manifest and
  that script agree. A separate file would also let the two drift apart in the
  one dimension the test exists to bind.
- **How the containment digest sees bytecode**: hashing `.pyc` CONTENT (catches
  in-place rewrites, but a `.pyc` embeds the source mtime, so the baseline churns
  and the containment check goes flaky red for non-leaks), versus folding the
  full PATH listing into the digest and leaving bytecode content out. Chosen: the
  path listing. It catches every leak that adds a path — which is what a mirror
  overwrite by `capability install` does — at zero flakiness cost, and the
  residual it does not catch is written down rather than implied.
- **Resolving the case-sensitivity gap**: a macOS CI leg, versus a recorded
  accepted risk plus a Linux-observable regression. Chosen: the record plus the
  regression. A macOS runner would exercise only the filesystem-fold half of a
  divergence whose other half (what gsd-core's readers do) is verifiable by
  reading source on any platform, and the ticket itself names an accepted-risk
  note as a legitimate resolution. The regression makes the Linux half executable
  so the decision cannot be silently reversed.
- **Scope of the `real_gsd_state()` fix**: only the copy the ticket names, versus
  both byte-identical copies. Chosen: both. The defect and the containment
  property are identical in the two suites; fixing one leaves the other blind to
  the same leak, which is the gap this ticket exists to close, not half of it.

Decided by: simplicity/LOC — every chosen option adds the fewest moving parts
(no new test file, no new CI leg, no new runner) while covering strictly more
than the alternative it replaces.
