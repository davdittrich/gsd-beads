## Alternatives Considered

**Finding 1 — how to stop line injection into the digest stream.**

- **Refuse any bundle entry whose path or link target holds a newline**
  (fail-closed, roughly four lines: compare `find | wc -l` against the count of
  NUL bytes from `find -print0`). Matches the file's existing posture and is by
  far the smallest change. Rejected: it closes only the reported vector. Two
  collisions survive it — a directory named `x -> y` is byte-identical to the
  line a symlink `x` pointing at `y` emits, and a symlink whose own name
  contains ` -> ` is ambiguous against its target — and both are the same
  severity, same threat model and same consequence as the one being fixed.
  Fixing one of three known members of a class is not a fix.
- **Hash each path with the hash tool and emit digests only** (no raw path in
  the stream at all): unforgeable by construction. Rejected on cost: one extra
  process per entry on top of the content hash, on a code path that runs at
  every session start and every subagent spawn, to buy nothing over escaping.
- **`find -print0 | sort -z`, hashing the NUL-delimited stream directly**: the
  most obviously correct shape. Rejected on portability — `sort -z` is not in
  POSIX, and this file's whole hash-tool dance (`sha256sum` versus `shasum`)
  exists because the macOS toolchain is a real target that cannot be tested
  here.
- **Chosen: tag-and-escape, one line per entry.** Three parameter expansions,
  no forks, no new tool dependency, and injective by an argument short enough
  to state in the comment: backslash is doubled first, so afterwards every
  backslash introduces an escape; newline and space are the only two other
  escapes; therefore no field contains the separator or a line break, and the
  kind tag keeps the three record shapes disjoint.
  Decided by: correctness first (it is the only candidate that closes all three
  collisions), then simplicity — it is fewer lines than the `-exec sh -c`
  construction it replaces, and it drops the dependency on whether the
  platform's hash tool escapes filenames.

**Finding 2 — how to bound a shell function's runtime.**

- **`export -f gsd_tools` and run it under `timeout bash -c`**: the idiom most
  people reach for. Rejected: the child then resolves the provider without a
  sourced file, so the resolver's `BASH_SOURCE` rung degrades to `command -v`
  and resolution silently differs on any host that does not set
  `CLAUDE_PLUGIN_ROOT`; and `export -f` on an undefined function turns case
  L2's 127 into a 1.
- **Background the install and poll for completion with a deadline**: no
  external dependency, works everywhere. Rejected: a polling loop plus signal
  handling in a hook whose stated contract is "never aborts the session" is
  more moving parts than the whole bug is worth, and this project's own
  automation rules forbid poll loops.
- **Leave it unbounded and document the hang**: the ticket permits a recorded
  decision. Rejected: the fix is six lines and the failure blocks every session
  start on the machine with no output at all.
- **Chosen: `timeout`/`gtimeout` prefix around `bash -c`, re-sourcing the
  resolver in the child.** Decided by: simplicity and behaviour preservation —
  it is the only option that leaves cases L1 and L2 and the D-13 resolution
  order untouched, and it degrades to today's exact behaviour where neither
  binary exists.

**Finding 3 — how to stop the sidecar write following a link.**

- **Write to a `$$`-suffixed temporary in the same directory and `rename` over
  the path with `mv -f`**: race-free, since `rename(2)` replaces a symlink
  rather than following it. Rejected: it trades one pre-plantable path for
  another (the temporary), needs its own guard, and triples the line count for
  a threat the ticket itself scores low.
- **Refuse to write when the path is not a regular file**, printing a reason:
  strictly more informative. Rejected: it hands an attacker a permanent denial
  of the fast path — plant the link once and every future session recomputes
  and reinstalls — which is a worse steady state than recreating the file.
- **Chosen: `rm -f` then write**, which is the ticket's own second option.
  Decided by: simplicity — one line, no new path, and the residual race is
  bounded by an attacker who already holds write access to the directory.
