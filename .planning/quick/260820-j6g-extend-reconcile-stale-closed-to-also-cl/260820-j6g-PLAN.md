# Quick Task: give `reconcile_stale_closed` reach over standalone problem-report issues

## Plan Header

- **Mechanism:** An opt-in `resolves_issues:` key in a completed plan's `SUMMARY.md` **frontmatter**.
  `reconcile_stale_closed` unions those ids into its candidate set alongside the existing
  `<beads-id>` set, then closes them through the same `filter_open_ids` live-status gate.
- **Forbidden:** Title/fuzzy text matching; scanning SUMMARY *body* prose for bd ids; globbing
  `*-SUMMARY.md` instead of reusing `discover_plan_files`; passing an unvalidated string into the
  `bd close` argv; touching `close_wave`, `_resolve_completed_task_ids`, `parse_depends_on`, or
  `parse_todo_files_block`; a new dependency (PyYAML) for a one-key read.
- **Audit:** `unittest` against `subprocess.run` stubbed by the existing
  `_make_close_wave_bd_side_effect`, asserting on the **observable `bd close` argv** — which ids are
  and are not in it — never that a helper was called. The identity-safety property gets its own
  regression test built from the real `18-02-SUMMARY.md` shape.

## Problem (bd `gsd-beads-72u`)

`reconcile_stale_closed` (`sync.py:1473-1516`) draws its entire candidate set from
`_resolve_completed_task_ids` (`sync.py:1342-1351`) — the union of every `<beads-id>` across a
phase's `PLAN.md` files. A standalone problem-report issue carries no `<beads-id>` anywhere, so the
backstop cannot reach it *by construction*. Confirmed live in Phase 18: `gsd-beads-he1/bzl/v43/t7a`
were all fixed and verified by Phase 17, yet `reconcile-stale-closed
.planning/phases/17-config-code-truth` reported `Closed 0 issue(s)`. Every such issue stays open
forever with no automated closure path.

**The trap this design has to avoid.** bd ids are already scattered through SUMMARY prose for
reasons that are *not* "resolved". `18-02-SUMMARY.md` mentions `gsd-beads-72u` — this very ticket —
as a follow-up it just **filed**. Any body-text scan would close the ticket that was opened one line
earlier. `.beads/` is untracked (`.gitignore:39-41`), so a wrong close is not recoverable from git —
the same risk class as Phase 18's `T-18-02-03`. The eligibility signal therefore has to be a
deliberate, structured, author-written marker, and nothing else.

## Alternatives Considered

| Approach | Performance / LOC | Simplicity | Ecosystem | Maintenance | Verdict |
|---|---|---|---|---|---|
| **`resolves_issues:` key in SUMMARY.md frontmatter** (chosen) | 2 regexes + 2 small functions + ~8 lines in `reconcile_stale_closed`; one extra `bd close` call only when markers exist | Reuses `FRONTMATTER_RE` + the `DEPENDS_ON_RE`/`DEPENDS_ON_BLOCK_RE` inline-plus-block idiom already shipped twice | YAML frontmatter is the format every `.planning/` artifact already carries | Marker is author-written and explicit; a stale marker is a no-op because `filter_open_ids` re-queries live status | **Chosen** |
| Scan SUMMARY body for `gsd-beads-\w+` | ~1 regex | Trivially simple | — | Closes `gsd-beads-72u` the moment `18-02-SUMMARY.md` merely names it as a follow-up; unrecoverable | Rejected — the ticket names this exact failure mode |
| Body marker line (`Resolves: id1, id2`) | ~1 regex | Comparable | — | Lives in free prose an editor can reflow, quote in an example, or copy into a code fence; no structural fence separates "declaring" from "quoting" | Rejected — frontmatter costs one extra regex and buys a hard structural boundary |
| Fuzzy title match (issue title vs. SUMMARY text) | Similarity scoring, tuning | Opaque | — | Non-deterministic closes on a destructive, unrecoverable operation | Rejected — explicitly forbidden by the ticket |
| Document the gap as a permanent manual step | 0 LOC | — | — | Rediscovered every milestone; the ticket's own fallback, not its preference | Rejected — user chose the mechanism |

**Why the chosen mechanism wins on the ranked criteria:** it is the only option that is
*structurally* immune to prose false positives (rank 1 — correctness on the one operation that
cannot be undone), it costs ~30 lines by cloning an idiom that already exists twice in this file
(rank 2), and it adds no dependency and no new file (ranks 3-4).

## Scope boundaries

- **`close_wave` is deliberately not extended.** It is wave-scoped and receives a plan-id list;
  `reconcile_stale_closed` is the phase-wide backstop and is what `execute:wave:post` and
  `verify:post` dispatch (`SKILL.md` Step 2b). Extending the backstop covers the automated path.
- **`_resolve_completed_task_ids` is not modified.** Its contract is "`<beads-id>` union" and
  `_compute_diverged` depends on that meaning. The marker set is a *sibling* source, unioned at the
  `reconcile_stale_closed` call site only.
- **gsd-core's `summary.md` template is not patched.** Teaching upstream to emit `resolves_issues:`
  is a separate change against a repo this plan does not own; file it as a follow-up if wanted.
