<objective>
`beads.epic_per=milestone` (B14) creates one epic shared across every phase in the current
milestone instead of one epic per phase. Forward-only (D-10): an already-created per-phase epic is
never retroactively folded into the milestone epic. Read fresh at each epic-creation call site
(D-11): a mid-milestone config change never disturbs a phase already mid-flight.

Purpose: gives users who prefer one epic per release (instead of one per phase) that granularity,
without disturbing existing per-phase epics from Phases 1-3 or requiring any destructive
re-parenting write.
Output: `resolve_milestone_epic()` and supporting helpers in `sync.py`, a `resolve_epic()` edit that
branches on the new `beads.epic_per` config key, a new `capability.json` config entry, and a
`TestMilestoneEpic` test suite.
</objective>
