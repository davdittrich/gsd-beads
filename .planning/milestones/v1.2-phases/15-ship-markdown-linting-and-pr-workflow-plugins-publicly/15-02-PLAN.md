## Alternatives Considered

- **Construct a minimal plugin-tree wrapper around the existing bundle, then `cp` to a scratch dir +
  fresh `git init` + `gh repo create --source=. --push`**: adds the four files a Claude Code plugin
  root requires and publishes from current file state with no history machinery.
  `https://code.claude.com/docs/en/plugins-reference` (2026) documents `.claude-plugin/plugin.json` at
  the repo root as the only hard requirement; `gh repo create --help` (gh 2.97.0, verified on this
  machine, 2026) documents `--source` as the existing-local-repo path.
- **Publish both capabilities from a single shared repository** (one repo, two plugin roots, two
  marketplace entries). Half the repositories to create, review, and keep in sync, and the marketplace
  schema supports it through a repository-plus-path source. Same doc,
  `https://code.claude.com/docs/en/plugin-marketplaces` (2026). Ruled out by locked decision D-00,
  which requires each plugin to have its own separate public repository, and by ROADMAP success
  criterion 1, which names two distinct repository URLs.
- **`git subtree split -P .gsd/capabilities/pr-workflow -b <branch>` then push that branch**: rewrites
  the bundle's commits into a synthetic branch whose root is the bundle, preserving Phase 14 history.
  `git subtree --help` (git 2.55.0, verified on this machine, 2026). Ruled out by D-00's locked "fresh
  init, no history extraction", and it would produce a root that is the bundle rather than the plugin
  root a marketplace install needs.

Decided by: simplicity/LOC. All three publish in one shot on a 17-file tree, so the ranked performance
criterion ties; the shared-repo and history-preserving options are each eliminated outright by locked
decision D-00, leaving the wrap-then-copy-and-init path as both the mandated and the shortest correct
one.
