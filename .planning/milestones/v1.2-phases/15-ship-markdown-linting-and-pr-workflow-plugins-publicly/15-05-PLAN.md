## Alternatives Considered

The alternatives below are about HOW the removal executes. Retaining the bundles is no longer a live
alternative: the operator's direct in-session instruction (quoted in `<objective>`) requires that
neither capability have files in this repository, which decides the question by instruction rather
than by any ranked criterion. It is recorded here as rejected-by-instruction, not weighed.

- **`git rm -r <path>` for each bundle, paired in one commit with the two un-ignore-line deletions and
  the `.gsd-capabilities.json` reconciliation** (chosen): removes the paths from the index and the
  working tree in one command each, leaving no untracked residue and no dangling ignore negation.
  `git rm --help` (git 2.55.0, verified on this machine, 2026). This is the exact three-part shape
  commit `4d83504` (2026-08-18) used for the two previously extracted plugins.
- **`git rm -r --cached <path>` plus leaving the files on disk**: untracks the paths so the repository
  stops shipping them while a local copy survives. Same doc-ref, `git rm --help` (git 2.55.0, 2026).
  Rejected: it leaves precisely the hand-editable, now-unversioned second copy the duplication concern
  is about, and files on disk in the repo are still files in the repo — which the operator's
  instruction rules out directly.
- **`rm -rf <path>` followed by `git add -A`**: reaches an identical end state with fewer commands.
  `git add --help` (git 2.55.0, 2026). Rejected: `-A` stages by whole-tree scan, which would sweep the
  pre-existing uncommitted `.gsd-capabilities.json` edit Task 1 recorded into this commit — the exact
  contamination T-15-36 mitigates against.

Decided by: maintenance overhead. All three are one-shot operations of identical cost, so performance,
size, and ecosystem support all tie; what separates them is what each leaves behind for the next
editor — an unversioned drifting copy under the second, an unrelated edit silently in the history
under the third.
