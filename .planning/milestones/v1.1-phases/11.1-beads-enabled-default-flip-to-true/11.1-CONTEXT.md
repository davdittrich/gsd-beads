# Phase 11.1: beads.enabled default flip to true - Context

**Gathered:** 2026-08-17
**Status:** Ready for planning

<domain>

## Phase Boundary

Flip the `beads` capability's default config value `beads.enabled` from `false` to `true` in the shipped plugin (`.gsd/capabilities/beads/capability.json`), so a fresh install runs with beads issue-tracking on out of the box instead of requiring a manual opt-in. This phase covers only the config default and its documentation surface — not any new beads functionality.

</domain>

<decisions>

## Implementation Decisions

### Flip scope
- **D-01:** Full doc sweep, not config-only. Update `beads.enabled` default in `.gsd/capabilities/beads/capability.json`, and every doc/skill asserting "default false": `README.md`, `.agents/skills/beads/PRIME.md`, `.beads/PRIME.md`, all 4 SKILL.md files under `.gsd/capabilities/beads/skills/` (beads-recall, beads-sync, beads-status, beads-migrate-todos), and `docs/prd-beads-capability.md`. — **Reversibility:** reversible — pure text/config edits, easy to flip back.

### Version bump
- **D-02:** Bump `capability.json` version `0.1.0` → `0.2.0` (minor). Signals the default-behavior change for new installs without implying a breaking API/schema change. — **Reversibility:** reversible.

### Existing-install migration
- **D-03:** Add a CHANGELOG entry noting the default flip. No repo has a `CHANGELOG.md` yet — create one at repo root, starting with this entry. Note explicitly that explicit `beads.enabled` values in a consumer's `.planning/config.json` are untouched; only installs that never set the key pick up the new default. — **Reversibility:** reversible.

### README wording
- **D-04:** README.md:54-56 ("The capability is off until `beads.enabled` is set `true`...") flips to state beads is on by default, and adds the opt-out instruction (`beads.enabled: false` in `.planning/config.json`) in the same breath. — **Reversibility:** reversible.

### Claude's Discretion
- Exact CHANGELOG.md format/header structure (Keep a Changelog style vs simple list) — no prior convention in this repo to match.
- Whether other historical `.planning/milestones/v1.0-phases/**` docs referencing the old default need updates — these are phase-history records of decisions made at the time (default was false then); leave as historical record, do not rewrite. Only currently-live docs (README, PRIME.md, SKILL.md, capability.json, PRD) are in scope per D-01.

</decisions>

## Existing Code Insights

### Reusable Assets
- None — this is a config-value + doc-text change, no new code paths.

### Established Patterns
- `.planning/config.json`'s per-project `beads: { enabled: true }` block already overrides the capability default in this repo (set manually across Phases 1-4, before this flip existed) — confirms explicit config always wins over the shipped default, which is the basis for D-03's "existing installs untouched" claim.

### Integration Points
- Consumers of the default value: `gsd-tools.cjs` config resolution reads `capability.json`'s `config.beads.enabled.default` when a project's `.planning/config.json` has no explicit `beads.enabled` key. No resolution-order code changes are in scope — only the literal default value.
