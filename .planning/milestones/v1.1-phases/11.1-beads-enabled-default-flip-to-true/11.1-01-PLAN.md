<objective>
Flip the shipped `beads.enabled` default to `true` and make the four beads skills honor it, so a
fresh install runs with beads issue tracking on out of the box.

Purpose: today the capability ships opt-in. Flipping only the schema default is not sufficient —
each skill duplicates the gate by reading `.planning/config.json` directly and stopping when the
key is absent. Both halves are required for the phase goal to hold.
Output: `capability.json` at version 0.2.0 with `beads.enabled` defaulting to true, and four
SKILL.md Step 1 gates inverted to opt-out polarity.
</objective>
