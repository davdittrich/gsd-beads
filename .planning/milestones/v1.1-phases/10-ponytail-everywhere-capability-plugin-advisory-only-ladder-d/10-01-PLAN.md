<objective>
Build the Claude Code plugin channel of the `ponytail-everywhere` capability: a
`ponytail-everywhere/` plugin subdirectory whose `SessionStart` and `SubagentStart` hooks emit
config-driven, role-tailored, level-tailored lazy-ladder reminder text, registered as a second
plugin in this repo's existing self-hosted marketplace.

Purpose: this is the only mechanism that reaches Task-spawned `gsd-planner`/`gsd-executor`/
`gsd-verifier` subagents. RESEARCH.md proved `SessionStart` context does not propagate into
subagents, and that `capability.json` `contributions[]` are functionally delivered at exactly one
lifecycle point (`plan:pre`, Plan 02). Every advisory reminder at execute/verify/ship time is
carried by this plan's hooks, not by a contribution.

Output: a validatable second plugin in `.claude-plugin/marketplace.json`, plus one runnable
assert-based smoke test for the hook script's config/level/role branching.

## Review findings incorporated (10-REVIEWS.md, antigravity)

This plan was revised after cross-AI review. All three findings are addressed here or in Plan 02;
none are deferred or rejected.

- **[MEDIUM] Inconsistent gsd-tools discovery (finding 1) — FIXED, root cause.** The 3-step
  resolution chain now lives in exactly one file, `ponytail-everywhere/hooks/gsd-tools.sh`, as a
  `gsd_tools()` shell function. `session-start.sh`, `tests/test-session-start.sh`, and every
  verification command in Plan 02 source that file instead of each re-deriving a path. Duplication
  was the cause of the drift the reviewer found, so the fix removes the duplication rather than
  patching the second copy.
- **[LOW] In-place `.planning/config.json` mutation (finding 2) — FIXED, no residual risk in this
  plan.** `gsd-tools` resolves the project root from the process CWD or an explicit `--cwd`
  (verified during this revision: `config-get ponytail.level --cwd <scratch>` reads the scratch
  project's config and leaves the repo untouched). The test harness therefore runs every config
  case against a scratch project directory under `mktemp -d` and never writes to
  `.planning/config.json` at all — no in-place edit, no `trap`-based restore, nothing left behind
  by a SIGKILL. This uses an existing gsd-tools flag; no `GSD_CONFIG_DIR` mechanism is invented and
  no gsd-core file is patched (D-01).
- **[LOW] `CLAUDE_PLUGIN_ROOT` unset in standalone test runs (finding 3) — FIXED.** The fallback is
  now an asserted behavior case, not an implicit assumption: the harness runs the script once with
  `CLAUDE_PLUGIN_ROOT` explicitly removed from the environment and once with it set to the plugin
  directory, and asserts both runs produce byte-identical output.
- **Suggestion: validate both plugins from repo root — ALREADY PRESENT, now explicit.** Task 1 and
  Task 2 both run `claude plugin validate . --strict` from the repo root, which validates
  `beads-lifecycle` and `ponytail-everywhere` together through the shared
  `.claude-plugin/marketplace.json`. An acceptance criterion now names both plugins so a run that
  silently covers only one cannot pass.

**Unrelated execution hazard found during this revision (not a review finding):** inline
`python3 -c` is blocked by this machine's shell allowlist
(`[BLOCKED — DO NOT RETRY] Interpreter 'python3' with inline code execution flag '-c' is blocked`).
