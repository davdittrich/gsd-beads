4. Git, worktree, planning, tracker, and installed-runtime state diverged enough that later sessions lost authoritative context and required repeated operator correction.

## Root Cause

The primary root cause was a mismatch between the real production invariant and the release/update invariant being tested. Production required **old and new sessions to remain executable across the update**. The implemented gates proved only **the new version's bytes, registry selection, and fresh command behavior**. Because versioned hook paths function as a live-session ABI, deleting old cache directories was a breaking change even when the new installation was perfect.

The systemic cause was authority fragmentation. Planner reports, summaries, reviews, verifier verdicts, Git branches, worktrees, runtime homes, plugin caches, GitHub issues, and Beads were allowed to disagree. When they disagreed, optimistic evidence was selected instead of halting on the strictest authoritative state.

## Corrective Actions

### P0 — Required before another Codex beads-lifecycle update

1. Resolve GitHub #8 with cross-process leases or equivalent retention: stage 1.5.x side-by-side, activate atomically, and delete a prior version only after its final session reference is released.
2. Add the exact concurrent-session regression: session A loads 1.4.1; process B installs 1.5.1; session A's retained hook path and a new session both exit 0.
3. Add a fail-closed post-update guard that inventories session-referenced hook paths and rejects an update if any becomes missing.
4. Treat the current 1.4.1/1.5.0 symlinks as containment only. Do not run another cache-cleaning update while they are needed.

### P1 — Release and verification controls

5. Make ship/release fail closed when the authoritative phase verifier is anything other than `passed`; `human_needed`, `gaps_found`, and behavior-unverified truths cannot be overridden by SUMMARY, REVIEW, CI, or current-state checks.
6. For production runtime changes, require one update receipt containing pre-state, exact mutation, old-session probe, new-session probe, post-state, and rollback result. Persist the receipt outside updater-owned caches.
7. Preserve marketplace ownership as an invariant. Any Git-to-local or local-to-Git source change requires explicit operator approval and its own rollback plan.
8. Reconcile local `main`, release worktree, remote `main`, `STATE.md`, `ROADMAP.md`, GitHub, and Beads before the next phase/release claim. Do not infer this reconciliation from a tag or install alone.

### P2 — Recovery hygiene

9. Audit registered worktrees and remove only those proven inactive, with explicit approval for destructive cleanup.
10. Restore a session report or equivalent immutable execution receipt for production mutations.
11. Keep the existing `/dev/shm` outside-ancestry rule and host-side runtime verification rule as mandatory gates.
