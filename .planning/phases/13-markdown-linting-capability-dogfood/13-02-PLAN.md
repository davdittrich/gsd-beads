## Review Response (13-REVIEWS.md, Antigravity lane)

**R-01 [MEDIUM] — "Plan 02's `verify.automated` invokes `pytest`, but the suite is authored
stdlib-only `unittest`; a `pytest`-less environment fails verification unnecessarily. Suggested
fix: add `python3 -m unittest discover ...` as a fallback."** — **Incorporated, with a stronger
form than the suggestion.** Rather than chaining `pytest || unittest` (which runs the suite twice
on any genuine failure and leaves two possible exit paths to reason about), the stdlib runner is
now the sole `<automated>` command in both tasks, and pytest is demoted to a secondary acceptance
criterion asserting the suite *also* passes there. Both tasks' `<verify>` blocks, both acceptance
criteria sets, the `<verification>` block, and a new `must_haves.truths` entry reflect this. Task 2's
`<action>` additionally pins the two things stdlib `discover` requires that `pytest` does not care
about: a `unittest.main()` `__main__` guard and `__file__`-relative fixture resolution.

## Alternatives Considered

The mechanism choice this plan makes is the **test runner** (the tool-selection and
artifact-contract choices are inherited from `13-01-PLAN.md`'s Alternatives Considered — rumdl over
markdownlint-cli2 and mdsmith — and are not reopened here).

- **`python3 -m unittest discover`** (selected): stdlib, Python 3.7+. Repeatable `-k` for
  OR-matched name filtering — `https://docs.python.org/3/library/unittest.html#command-line-interface`
  (`-k` documented since 3.7; `discover` since 3.2). Verified live on this repo 2026-08-18 against
  `.gsd/capabilities/beads/tests` (`Ran 1 test ... OK` under `-k bd_missing`).
- **`pytest`** (retained as a secondary check, not the gate): `https://docs.pytest.org/en/stable/`
  — v9.0.3 confirmed installed here 2026-08-18, and it is the runner
  `.planning/milestones/v1.0-phases/04-adoption/04-VALIDATION.md` records as this repo's
  convention. Not selected as the primary because it is a third-party dependency that this suite's
  source does not use a single API from, so requiring it buys nothing and can only subtract
  availability (review finding R-01).
- **`nose2` / `ward` / any new framework**: rejected without further evaluation — adding a
  dependency class to run tests that the standard library already runs unchanged fails every
  ranked criterion at once.

**Decided by:** maintenance overhead (rank 4) is the only criterion that discriminates here —
performance, LOC and ecosystem are all a wash for ~10 tests whose source is byte-identical under
either runner, so the tie breaks toward the runner that can never be missing. Keeping pytest as a
secondary assertion preserves the 04-VALIDATION.md convention at zero cost.
