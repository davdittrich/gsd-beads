## Alternatives Considered

- **Retain the Patch 2 dual-read path:** Keep the current machine-local task read beside the native resolver. Primary source: `plugins/beads-lifecycle/.gsd/capabilities/beads/GSD-CORE-PATCH.md` (reviewed 2026-09-01). Rejected because the duplicate path can satisfy execution while the installed resolver is broken, making CUT-01 unfalsifiable and increasing work per task.
- **Use project-overlay or direct-adapter success as the cutover oracle:** Exercise the tracked adapter or the project-scoped capability without proving global selection. Primary sources: https://github.com/open-gsd/gsd-core/blob/next/docs/reference/capability-manifest.md and https://github.com/gastownhall/beads/blob/main/docs/reference/index.md (accessed 2026-09-01). Rejected because neither mechanism traverses the installed global registry path required by CUT-01.
- **Introduce a persistent blue-green cutover harness:** Maintain parallel workflow variants and switch between them. Primary source: https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-40r4.pdf (accessed 2026-09-01). Rejected because this is one shared local workflow block with an exact byte restore, not a traffic-bearing deployment; the additional harness would add code and another state surface without improving rollback.
- **Locate the post-removal tracer:** Load the tracked `sync.py` through `importlib.util.spec_from_file_location`/`module_from_spec`, call its existing `parse_plan(plan)`, select the sole `type == "tracer"` task, validate its native/legacy identities, and extract commands from that parsed task's `verify` field. Primary sources: current tracked `parse_plan` (inspected 2026-09-01) and the [Python 3.14 importlib recipe](https://docs.python.org/3/library/importlib.html#importing-a-source-file-directly) (accessed 2026-09-01). Alternatives: retain literal opening-tag slicing (current plan inspected 2026-09-01), rejected because harmless `plan:post` attributes change the opener; or add a second stdlib ElementTree/manual XML parser, whose [Python 3.14 XML API](https://docs.python.org/3.14/library/xml.html) was accessed 2026-09-01, rejected because it duplicates the tracked plan grammar.
- **Preserve Patch 1 retained regions while retiring stale prose:** Use stdlib `ast.get_source_segment` only to locate the complete raw source of `check_patch`, `check_shipmd_patch`, and `TestCheckShipmdPatch`; persist each pre-edit UTF-8 byte region, derive its sole permitted post-edit bytes through four exact count-guarded replacements, and compare the post-edit regions byte-for-byte. Primary sources: [Python 3.14 `ast.get_source_segment`](https://docs.python.org/3/library/ast.html) and [Python 3.14 `hashlib`](https://docs.python.org/3/library/hashlib.html) (accessed 2026-09-01). Alternatives: AST structural normalization with `ast.dump`, rejected because removing docstring nodes creates a second semantic model and misses comments/whitespace; or token filtering with [Python 3.14 `tokenize`](https://docs.python.org/3.14/library/tokenize.html) (accessed 2026-09-01), rejected because token classification still needs separate policy maps and does not make the exact allowed post-source bytes the contract.

Decided by: performance. The selected path invokes the already-shipped public resolver once per proof, removes the duplicate per-task read, and adds no coordinating layer. For verifier mechanics, one AST location pass plus direct byte comparison avoids recursive normalization and parallel policy maps; simplicity/LOC, ecosystem support, and maintenance all reinforce that performance-first choice.
