**Why it is one-way.** `.github/workflows/release.yml` triggers on `push: tags: ['v*.*.*']`.
Deleting a tag is a ref *deletion* push and matches no trigger, so the deletion itself fires
nothing. But recreating `v1.3.0` later would be a tag push, which publishes a brand-new GitHub
Release from whatever `main` looks like then — not a restore of the withdrawn one. There is no
clean undo.

**What was verified live on 2026-08-20, so the decision rests on facts rather than the ROADMAP's
older description:**

- `git ls-remote --tags origin` shows `refs/tags/v1.3.0` -> `70f4c37` (annotated) dereferencing
  to `55855cd`. The tag does still resolve on the remote.

  already gone, so the release artifact is not what is being removed here.
