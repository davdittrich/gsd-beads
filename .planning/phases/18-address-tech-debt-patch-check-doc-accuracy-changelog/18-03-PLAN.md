<objective>
Make `sync.py` tell the truth about its own output stream, and make its patch-check messages
uniformly recognizable — then make the two skills that consume those messages stop depending on
the message text at all.

Purpose: `17-REVIEW.md` WR-01 and WR-02 are two halves of one defect shape. WR-01 is a docstring
asserting a convention that does not exist in the code (and a `#` comment repeating the same false
claim at the call site, which the review did not name). WR-02 is two message templates that the
consuming skills' surfacing rule cannot see, because that rule greps for a marker those templates
never carry. D-03 fixes both halves rather than either: mark the messages AND stop keying the rule
on the mark, so the next forgotten prefix is a cosmetic miss instead of a silent one.

Output: four uniformly marked message templates with per-target test coverage, a truthful
docstring plus a pinning comment on the line the drift will next threaten, and two SKILL.md
surfacing rules keyed to `check_patch`'s exit code.

**Tracer-first does not apply to this plan.** These are three independent edits inside one module
and two documents — there is no stack to slice vertically. What tracer-first is actually for here
is served by Task 1's TDD gate: the marker assertions go red against today's templates before the
prefix exists, which is the same "prove it fails, then prove it passes" evidence a tracer's
end-to-end `<verify>` would provide. Recorded per TRACER_MODE=true rather than silently skipped.

**Why this plan is wave 2 and depends on 18-01.** Its suite-green criterion cannot pass until
18-01 lands. From the plugin tree today the suite reports `FAILED (failures=6)`; all six are
`strips_task_body` assertions gated on a live `check_execute_plan_patch() == 0`, which is false
while the machine-local `execute-plan.md` patch is missing. Verified causal on 2026-08-20 by
re-running the identical suite with `CLAUDE_CONFIG_DIR` pointed at a tree holding patched copies:
`Ran 248 tests` / `OK`. That coupling of a unit suite to machine-local state is itself a latent
defect; ticket it in `bd` if it is not already tracked, and do not fix it here — it is outside
Phase 18's boundary.
</objective>
