## Alternatives Considered

D-08's reapply mechanism is a real technical choice (CONTEXT.md leaves the *how* open), so this
section is a real comparison rather than the `N/A` the other three plans in this phase carry.
Citations are file:line and live command output from this machine on 2026-08-20 — a machine-local
file-restoration problem has no meaningful published-library alternatives to cite.

| Option | Mechanism | Evidence | Verdict |
|--------|-----------|----------|---------|
| A (chosen) | Insert the verbatim block at the documented anchor, once per file, four times | `GSD-CORE-PATCH.md:102-160` and `:207-244` already carry the exact anchors and byte-exact bodies; anchor regions confirmed byte-identical across both homes | **Chosen** |
| B | `cp` the `~/.claude/gsd-local-patches/` backup over the live files | `diff` shows the backup differs from the live `~/.claude` file *only* by the patch block (28 lines ship.md, 9 lines execute-plan.md) — so it would work for that home, but `~/.codex` has no backup at all (`ls ~/.codex/gsd-local-patches/` → `No such file or directory`) and cross-home copying is prohibited by the 46/60-line templating divergence | Rejected |
| C | `/gsd-update --reapply` driving `verify-reapply-patches.cjs` | The tool exists in both homes (`bin/verify-reapply-patches.cjs`, 17430 bytes) but ROADMAP Ship-step check #4 records it exiting 1 with most reported "missing" lines being legitimate base-version churn, and it is backup-driven so it cannot reach `~/.codex` either | Rejected |
| D | Write a small idempotent reapply script | Would be new code with exactly one caller, for an operation that is four Edit calls, on files this repo does not own | Rejected (YAGNI) |

**Ranked criterion that decided it: simplicity / lines of code.** Option A adds zero new code,
works identically on both homes, and cannot revert unrelated content the way a whole-file copy
(B) can. Option B is *faster* for the `~/.claude` home but needs a second mechanism for
`~/.codex`, so it costs two procedures instead of one — and its main asset, the backup, is more
valuable as an independent byte-equality oracle for A's result (Task 1's second acceptance
criterion) than as A's replacement. Performance is not a discriminator: all four options are
sub-second, one-time operations.
