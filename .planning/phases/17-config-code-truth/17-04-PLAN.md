## ROADMAP Success Criterion 4 versus CONTEXT.md D-08 — surfaced, not silently resolved

These two source artifacts disagree, and the disagreement is load-bearing enough that it gates a
task rather than being settled in prose.

- **ROADMAP.md Phase 17, Success Criterion 4** (written 2026-08-19) states that **both CLI
  subcommands and both flag spellings survive** the refactor, and calls this "load-bearing and
  untested today".
- **CONTEXT.md D-08** (written 2026-08-20, after the roadmap, in `/gsd-discuss-phase`) states the
  opposite: collapse to **one parameterized CLI verb, hard break, no aliases**, every caller

unifying the CLI would keep the suite green while silently breaking `beads-status/SKILL.md` Step
2d, which invokes the ship-md verb by name. That worry is answered twice over: D-09 lands the
missing CLI coverage *before* the merge, and D-08 requires every caller updated in the same
commit. Criterion 4's literal "both subcommands survive" clause is what does not survive.

**Criterion 5 is untouched and fully honored** — both *Python function names* survive as thin
wrappers, so the assertions in `TestCheckShipmdPatch` and `TestCheckExecutePlanPatch` pass

## Alternatives Considered

Mechanism choice: how two structurally identical detectors become one, and what happens to the
public CLI surface.

- **Table of literals + one parameterized reader, both wrappers retained (CHOSEN).** A
  module-level dict keyed by target name, each entry carrying filename, marker constant, marker
  version and its consequence text; one reader walks it; the two existing function names stay as
  one-line wrappers. Sources: the repo's own idiom for a small fixed variant set is a plain
  module-level tuple/dict of literals plus a direct dispatch — see `` `sync.py` `` lines 121-127
  (`LIFECYCLE_DISPATCH_POINTS`, 2026) and the analysis in
  `` `.planning/phases/17-config-code-truth/17-PATTERNS.md` `` (2026-08-20); the parameterized
  verb rides Python's standard subparser mechanism,
  <https://docs.python.org/3/library/argparse.html#sub-commands> (Python 3.13, 2026).
  **Decided by:** simplicity/LOC — it removes roughly 50 duplicated body lines, it is the only
  option that gives D-10's per-entry version field a home, and retaining the wrappers costs two
  lines while preserving four existing test mocks and two call sites unedited.

- **Shared private helper, both CLI verbs kept.** Extract the common body into one private
  function; the two public verbs and both flag spellings stay. Sources:
  `` `.planning/ROADMAP.md` `` Phase 17 Success Criterion 4 (2026-08-19) requires exactly this,
  and `` `.planning/phases/17-config-code-truth/17-DISCUSSION-LOG.md` `` Area 4 (2026-08-20)
  records it as the standing recommendation until the caller grep. **Decided by:** maintenance
  overhead — it removes the same duplicated lines but leaves two subparsers, two flag spellings
  and two dispatch branches permanently, each needing its own test, for a CLI surface with zero
  callers outside this repository. Superseded by CONTEXT.md D-08; surfaced to the developer at
  Task 2 rather than dismissed.

- **Collapse with a one-release alias window.** Ship the new verb, keep the old two as deprecated
  aliases for one release, then delete. Source: gsd-core's own removal precedent,
  `runtime.hostBehaviors.reviewerCli` — <https://github.com/open-gsd/gsd-core/issues/2801>
  (2026) — one release as a derived alias, then deletion, warning never error. **Decided by:**
  maintenance overhead — that precedent exists for an *externally visible* contract. A grep of
  this repo establishes the two verbs have no README exposure and no caller outside it, so an
  alias window would carry deprecation machinery through a release to protect callers that do not
  exist. Explicitly considered and not followed, per D-08.
