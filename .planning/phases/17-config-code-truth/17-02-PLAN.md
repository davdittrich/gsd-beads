<objective>
Close TRUTH-03: the `lifecycle-dispatch` PostToolUse hook stays correct when gsd-core ships PR
**#3687**, which adds generic `kind == "step"` dispatch at `plan:post` and `verify:post`. Merged
to `next` at commit `ea59430` on 2026-08-19, 6h50m after the v1.11.0 release cut — so it is
unreleased today and lands at the next cut, and this plan must be correct both before and after.

Two distinct problems, both answered here:

1. **Double dispatch.** Once native dispatch exists at those two points, the hook fires *and*
   gsd-core dispatches. `create_issues` is idempotent so no duplicate issues appear, but the work
   is wasted and the `additionalContext` output doubles.
2. **The `allow_strip` protection is bypassed, silently.** Native dispatch invokes the
   `beads-sync` *skill*, which runs `sync.py create-issues <plan>` — a CLI verb with no strip
   flag, so `create_issues`' `allow_strip=True` default applies and `strip_task_bodies` returns
   via the native path even though the hook path deliberately disables it. **The ruling this
   requirement must record, recorded:** an explicit registry dispatch IS a different principal
   from a string-matched hook, so the strip is permitted on the native path and governed by
   `beads.sync_mode` (D-06), while the hook path stays permanently conservative (D-03).

`execute:wave:pre` and `execute:wave:post` are **not** covered by #3687 and have no upstream fix
released, merged, or in an open PR. The hook remains necessary there and must not be deleted.

Purpose: this is time-boxed by a release that can land at any cut. Re-run the upstream status
check immediately before the milestone ships.

Output: a read-only, fail-open native-dispatch probe (D-05: grep the installed workflow file for
the generic-dispatch text #3687 adds, not version-sniffing — the release carrying #3687 has no
version constant to sniff yet); a gate on two of the five dispatch points; `beads.sync_mode` wired
to the native path's strip decision; and `GSD-CORE-PATCH.md` recording the mechanism and its
revert condition.

bd parent issue: `gsd-beads-he1` (P1).

**Cross-decision note, stated so no reader has to infer it:** D-06 needs a `beads.sync_mode`
reader, and this plan lands before `17-03` (TRUTH-01), which owns the `capability.json`
declaration change and the doc sweep. This plan therefore adds the two-line `read_sync_mode`
accessor as a prerequisite of D-06's wiring; `17-03` owns everything else about the key. The
intermediate state is safe: until `17-03` lands, `capability.json` still declares `off`, and an
on-disk `"off"` yields `allow_strip = ("off" != "mirror")` = `True`, which is exactly the
`allow_strip=True` default that call site has today. No behavior regresses mid-phase.
</objective>

## Alternatives Considered

Mechanism choice: how the hook learns that the installed gsd-core now dispatches `kind == "step"`
hooks natively at `plan:post` and `verify:post`.

- **Region-scoped marker probe on the installed workflow files (CHOSEN).** Read
  `$CLAUDE_CONFIG_DIR/gsd-core/workflows/{plan-phase,verify-work}.md`, isolate the region that
  belongs to the point's own `render-hooks <point> --raw` call, and look for a generic step arm
  there. Source: the PR itself — <https://github.com/open-gsd/gsd-core/pull/3687> (merged to
  `next`, commit `ea59430`, 2026-08-19; re-verified live 2026-08-20) — plus the installed
  1.11.0 files themselves, `` `~/.claude/gsd-core/workflows/plan-phase.md` `` and
  `` `~/.claude/gsd-core/workflows/verify-work.md` `` (read 2026-08-20), which supply the exact
  pre-#3687 shape the probe must classify as not-detected. **Decided by:** simplicity/LOC — it is
  the function shape already in this file twice (`check_shipmd_patch`'s read-only, fail-open,
  name-the-path-checked discipline), and it is the only option whose failure mode is bounded and
  pre-declared: a false negative degrades to today's working double dispatch.

- **Version-sniffing the installed gsd-core.** Compare the installed version against a hardcoded
  "ships in 1.12.0" threshold. Source: `` `~/.claude/gsd-core/VERSION` `` reads `1.11.0`
  (checked 2026-08-20), and the release that will carry #3687 does not exist yet — so the
  threshold constant cannot be filled in today without guessing. **Decided by:** maintenance
  overhead — a stale or wrong threshold makes the whole design wrong *silently*, with nothing in
  the system re-checking it, which is precisely the failure class that forced this milestone's
  roadmap revision. Explicitly rejected by CONTEXT.md D-05.

- **Accept permanent double dispatch and add no detection at all.** Zero new code; duplicate
  issues are already impossible because `create_issues` is idempotent, a property pinned by
  `` `tests/test_sync.py` `` `class TestIdempotency` and documented in `` `CHANGELOG.md` ``
  §0.3.1 (2026-08-19). **Decided by:** it does not meet the requirement. TRUTH-03 has two
  problems and this option touches neither — the requirement asks the hook to stay *correct*,
  not merely safe, and the `allow_strip` bypass (problem 2) is untouched by doing nothing.
  It also leaves no signal at the moment the hook becomes redundant.

**Sub-choice within the chosen mechanism — region-scoped versus whole-file grep.** This is
settled by evidence, not preference: a whole-file `kind == "step"` grep is a **false positive on
the shipped 1.11.0 tree today**. `plan-phase.md` carries three such occurrences (at the plan:pre
generic contract, the auto-chain UI branch, and the intel step read) and `verify-work.md` carries
one at its verify:post region, filtered to `ref.skill == "secure-phase"`. A whole-file grep would
report "native dispatch present" on an install that has none, the hook would stand down, and the
sync would be **missed** — the one failure direction D-05 forbids. Region scoping plus a
capId/skill-filter exclusion classifies both shipped files correctly as not-detected.
