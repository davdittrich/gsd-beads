<wave_granularity_fact>
01-RESEARCH.md resolved PRD §12's open question against gsd-core source: `execute:wave:post`
fires **once per wave**, after every plan in that wave has merged, and the surrounding workflow
step carries `WAVE_PLAN_IDS`, a space-separated list of the plan ids that completed. There is no
`execute:plan:post` and no `execute:task:post` point in the closed twelve-point vocabulary.

The direct consequence, and the pitfall this plan exists to avoid: a close-one-issue design
silently misses every task past the first in any wave that completed more than one task. The
`close-wave` subcommand therefore takes a list of plan ids and iterates every task of every one
of them, always — including when the list happens to have length one.
</wave_granularity_fact>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `WAVE_PLAN_IDS` → filesystem plan lookup | Plan ids arrive from the orchestrator's wave context and are used to locate plan files. |
| PLAN.md task ids → `bd close` argv | Issue ids read from artifacts cross into an external process. |
| Capability install → user's project | Installing an overlay grants it instruction surfaces the agent will later follow. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Tampering | `close-wave` plan-id resolution | medium | mitigate | Treat each incoming plan id as an opaque token matched against plan files discovered inside the resolved phase directory; never join it onto a path. Reject ids that match no discovered plan and reject any resolved path that escapes the phase directory. |
| T-01-08 | Tampering / Elevation of Privilege | `bd close` invocation | high | mitigate | Same control as T-01-01 and T-01-05: argv lists passed to `subprocess.run` with shell interpretation left disabled; ids and the reason string are discrete argv elements. |
| T-01-09 | Repudiation | Automatic wave close | medium | mitigate | Every close carries a reason string naming the wave, so bd's own history records why an issue closed and an operator can distinguish an automatic wave close from a manual one when investigating Phase 3 divergence. |
| T-01-10 | Elevation of Privilege | Project-scope capability install and consent | high | mitigate | Installation goes through `gsd capability install --scope project` and its consent disclosure, which enumerates the contributed skill stems, at a blocking human checkpoint. The install is never run with an auto-approve flag, so the instruction surfaces the agent will follow are reviewed by a human before they are active. |
</threat_model>
