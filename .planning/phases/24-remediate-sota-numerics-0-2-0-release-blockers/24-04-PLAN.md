<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plan document to gate stderr | Attacker-influenced document text is interpolated into diagnostics an agent then reads. |
| gate stderr to the session context window | Whatever the gate prints is consumed by the agent that triggered the halt. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-24-13 | Denial of Service | unbounded diagnostic interpolation | high | mitigate | A crafted document can flood the reader's context through one stderr line; Task 1 bounds every document-derived span and pins the bound with worst-case fixtures. |
| T-24-14 | Spoofing | truncated spans read as complete | medium | mitigate | Truncation without a marker lets a cut span look like the whole value; the helper appends an elision marker only when it cut, and a test asserts short messages carry none. |
| T-24-15 | Tampering | newline injection into diagnostics | medium | mitigate | Spans are truncated to a bounded width, so a document cannot forge extra violation lines at scale; the per-run remediation count check pins that exactly one remediation line is emitted. |
| T-24-16 | Denial of Service | diagnostics change moving a verdict | medium | mitigate | Task 1 and Task 2 both re-run the corpus sweep against the plan 24-03 table, so a message-only change that alters an exit code stops the commit. |
</threat_model>

## Alternatives Considered

- **Slice with an explicit elision marker**: one small helper that cuts a span at a fixed width and appends a marker only when it cut, applied at each interpolation site. Stdlib only, and the marker distinguishes truncation from absence, which is what makes a bounded diagnostic still trustworthy. The GSD capability's own precedent already specifies this shape for its diagnostics (`.gsd/capabilities/sota-numerics/NOTES.md`, 2026).
- **`textwrap.shorten` from the standard library**: collapses whitespace and truncates on a word boundary with a configurable placeholder (`https://docs.python.org/3/library/textwrap.html`, 2025). Nicer output for prose, but it normalises whitespace, so a quoted heading no longer matches the document byte for byte and a reader cannot search for what was quoted.
- **Emit full diagnostics at a lower verbosity and a summary by default**: keep the whole span behind a verbosity flag rather than cutting it. Standard logging practice (`https://docs.python.org/3/howto/logging.html`, 2025), but the gate has one stderr stream and no caller that could pass a flag, since the gate command is constant by design, so the flag would be unreachable.

Decided by: simplicity. Option one is a handful of lines with no whitespace surprises and no unreachable configuration; option two rewrites the quoted bytes it is meant to quote; option three adds a control surface the gate's constant command cannot use. Performance is irrelevant at these sizes.

### Internal design alternatives

- **Deduplicate and sort the year list before truncating versus truncating in document order**: sorting makes the message stable when the same years appear in a different order, so the same defect always reads the same way.
- **Carry the line number in the violation tuple versus recovering it in the printer**: only `validate_plan` knows which offset the reason is about, so recovering a line in the printer would guess.
