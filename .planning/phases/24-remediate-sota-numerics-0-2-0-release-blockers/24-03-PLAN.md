## Alternatives Considered

- **Bound the existing regexes in place**: replace the unbounded leading-whitespace class in the bullet and table-row scans with a counted zero-to-three class, and switch the frontmatter phase parse from first-match to exactly-one. Two regex edits and one branch edit, inside functions the suite already covers, and the zero-to-three bound is the value CommonMark itself defines for top-level block starts (`https://spec.commonmark.org/0.31.2/#list-items`, 2024).
- **Track list nesting depth during a structural pre-pass**: build the list hierarchy first and count only depth-zero items, rather than reading indentation off each line. Handles the case where a top-level item's own continuation lines are indented past three spaces, which a flat bound cannot see. It duplicates block structure the masking pre-pass added in plan 24-01 already walks (`.gsd/capabilities/sota-numerics/NOTES.md`, 2026), and the corpus contains no entry that needs it.
- **Delegate both parses to a Markdown and YAML library pair**: `markdown-it-py` for the entry structure and `PyYAML` for the frontmatter, so neither indentation nor duplicate-key handling is hand-written; PyYAML raises on a duplicate mapping key in its stricter loaders (`https://pyyaml.org/wiki/PyYAMLDocumentation`, 2025). It is the most correct and the least code inside this file, but it puts two runtime dependencies inside a lifecycle hook whose install path is a plain file copy, where an import error becomes a halt.

Decided by: simplicity. Option one is three small edits to parsers that already exist, which is exactly what D-01 permits and nothing more; option two writes a second structural walk for a case the corpus does not contain; option three trades a dependency-free single file for correctness the sweep shows is not needed. Performance is indistinguishable at corpus scale.

### Internal design alternatives

- **Report frontmatter ambiguity as exit 2 versus exit 1**: exit 2 matches the body parse's existing raise-to-exit-2 path and keeps "the gate could not identify the phase" distinct from "the plan does not comply", so it is chosen over folding ambiguity into the compliance verdict.
- **Bound the table-row scan alongside the bullet scan versus leaving it**: the two carry the identical unbounded class and describe the same construct in two shapes, so bounding only one would leave the bypass open through the other.
