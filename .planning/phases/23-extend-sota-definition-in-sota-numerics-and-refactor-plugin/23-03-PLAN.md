## Alternatives Considered

- **Structural JSON diff against `origin/main` with an explicit allowed-key allowlist**: parse both revisions of `capability.json`, walk every key path, and fail on any difference outside `version`, `description`, `gates[0].description`, and the one config description. Paired with a docstring-stripped AST comparison for the Python file. Citation: the gate object being frozen, `` `.gsd/capabilities/sota-numerics/capability.json` `` lines 75-89, read directly and verified 2026-09-06; both commands were run green against the unmodified tree on 2026-09-06 before this plan was written, so the check is known to pass on a no-op rather than assumed to.
- **Text diff review plus the existing smoke tests**: read `git diff` by eye and trust `tests/test-gate-script-resolution.sh` and `tests/test-session-start.sh` to catch a broken gate. Citation: `` `.github/workflows/ci.yml` `` — the three CI steps, read and verified 2026-09-06. Rejected on coverage: those two scripts exercise script-path resolution and the session-start hook, not the manifest's predicate string, so a reformatted or subtly altered `command` passes both while changing what the gate runs.
- **JSON Schema validation of the manifest**: let gsd-core's loader validate `capability.json` on install and treat a clean load as proof. Citation: `` `/home/dd/.claude/gsd-core/bin/lib/capability-validator.cjs` `` lines 2672-2735, read and verified 2026-09-06. Rejected on the same ground, more sharply: shape validity is not contract identity. A manifest with a completely different `predicate.command` is still schema-valid, so the check cannot distinguish the change this plan forbids from the change it permits.

Decided by: simplicity. Performance is a wash — all three checks complete in well under a second on a 91-line manifest and a 340-line script, so the ranked criterion above simplicity does not separate them and the decision falls to the next one. The structural diff and the AST comparison each express the invariant directly in a single self-contained command with no new file added to the repository, which matters under a decision that forbids new test infrastructure; the two alternatives need either sustained human diff-reading discipline or a new schema artifact to approach the same coverage, and still would not reach it.

### Internal design alternatives

- **Docstring-stripped AST comparison versus a comment-stripped text diff**: the AST comparison is exact and ignores formatting, blank lines, and comment placement by construction, where a text filter would need its own rules for line continuations and multi-line strings. Comments never appear in a Python AST, so stripping only docstrings is sufficient and complete.
- **One task for both manifests versus one task each**: one each. The version fields must agree, and the cross-check belongs in the second task where both files are final; splitting also keeps each task's freeze assertion scoped to a single file's allowlist.
- **Rewriting `gates[0].description` versus leaving it alone**: rewriting. It is agent- and contributor-facing prose inside the self-compliance scope, and it currently spends most of its length restating which other capabilities use skip — reasoning NOTES.md carries in full and ships alongside.
