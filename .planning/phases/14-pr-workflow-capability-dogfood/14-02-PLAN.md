## Alternatives Considered

### Mechanism: how "does an open PR exist for this branch" is answered

- **`gh pr list --head <branch> --state open --json number,url` (selected)** —
  `https://cli.github.com/manual/gh_pr_list`, `gh` v2.97.0 (2026-07-31); server-side state filter,
  returns an empty array cleanly. Verified live this session against this repo's `main` (empty case)
  and against `cli/cli` (non-empty case).
- **`gh pr view <branch> --json state,number`** — `https://cli.github.com/manual/gh_pr_view`, same
  release. Verified live this session to return exit 0 and `{"number":14193,"state":"MERGED"}` for a
  merged PR, so it answers "a PR exists" rather than "an open PR exists" unless the caller also
  inspects `state` — an extra branch that exists only to compensate for a missing filter.
- **Scraping `gh`'s human-readable "no pull requests found" stderr** — the message text `gh` itself
  has had defects in (`https://github.com/cli/cli/issues/5284`, filed 2022). Fragile, unstructured,
  and localizable.

**Decided by:** simplicity/LOC — the state-filtered list call answers the question in one branch with
no post-filtering and no text matching; both alternatives require extra reconciliation code to reach
the same answer, and the third is not stable API surface.
