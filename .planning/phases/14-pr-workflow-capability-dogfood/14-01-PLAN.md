## Alternatives Considered

### Mechanism: how PR check status is read from GitHub

- **`gh` CLI v2.97.0 (selected)** — `https://github.com/cli/cli/releases/tag/v2.97.0`, released
  2026-07-31; installed binary verified this session as `gh version 2.97.0 (2026-07-31)`. Owns auth,
  pagination, and the `CheckRun`/`StatusContext` union-type normalization behind the `bucket` field.
- **GitHub REST API via Python stdlib `urllib.request`** — `https://docs.github.com/en/rest/checks/runs`,
  REST API version header `2022-11-28`. Zero new binaries, but requires hand-rolling token discovery,
  pagination, and the same union-type reduction `gh` already performs — the exact "Don't Hand-Roll"
  trap 14-RESEARCH.md flags.
- **`PyGithub`** — `https://pypi.org/project/PyGithub/`, v2.x releases through 2024. Ergonomic
  object model, but introduces a first PyPI runtime dependency into a capability family whose
  established discipline (`lint.py`, `sync.py`) is stdlib-only plus one external binary, and still
  leaves the caller to reduce raw check states.

**Decided by:** simplicity/LOC — `gh pr checks --json bucket` collapses auth, pagination, and
union-type normalization into one argv-list subprocess call, against roughly a hundred lines of
hand-rolled equivalent in either alternative. Performance is a non-differentiator (one process
spawn per wave, seconds-scale budget), so the next-ranked criterion decides.

### Mechanism: how a four-state status becomes a single gate predicate

- **Derived boolean `pr_gate_ok` gated with the existing `artifact-frontmatter-equals` (selected)** —
  precedent `.gsd/capabilities/markdown-linting/capability.json`, shipped in this repo 2026-08-18
  (Phase 13), which reduces N rumdl findings to one int gated with `equals: 0`.
- **A new `artifact-frontmatter-in` predicate kind in gsd-core** — installed evaluator
  `~/.claude/gsd-core/bin/lib/gate-predicate-evaluator.cjs`, read this session 2026-08-18; its
  `equals` handling is single-scalar with strict comparison and no array/OR support, so tri-state
  would require patching shared evaluator code outside this capability's boundary.

**Decided by:** maintenance overhead — the derived-field reduction lives entirely inside this
capability's own bundle and survives Phase 15's extraction to a standalone plugin unchanged, whereas
a new predicate kind would add a second machine-local, unmerged gsd-core patch to carry alongside
the `ship.md` dispatch patch already flagged in STATE.md.
