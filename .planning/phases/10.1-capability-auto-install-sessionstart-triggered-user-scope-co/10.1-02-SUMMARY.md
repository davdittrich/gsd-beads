# Phase 10.1 Plan 02: Extend capability auto-install to `ponytail-everywhere` Summary

**Vendored the `ponytail` capability bundle and the auto-install script into the second plugin (`ponytail-everywhere`), added a CI parity gate to prevent the two vendored copies from silently diverging, and confirmed via a real marketplace install that subdirectory-sourced plugins get the same plugin-cache layout as root-sourced ones.**

## Accomplishments
- `ponytail-everywhere` now ships its own `.gsd/capabilities/ponytail/` bundle (previously shipped none)
- `capability-auto-install.sh` vendored byte-identical into `ponytail-everywhere/hooks/`, wired into `session-start.sh` ahead of the `ponytail.enabled` early exit (D-02 preserved)

## Decisions Made
- Real marketplace install/verification performed directly by the orchestrator on explicit user instruction ("you run this for me"), rather than deferring the checkpoint indefinitely — this is the only way to empirically test Claude Code's live plugin-cache behavior, which no static code read can substitute for.
- The local-path marketplace used for the install (`/home/dd/projects/gsd-beads` added as a local-scope marketplace) is 43 commits behind `origin`. This is accepted as sufficient for A2 (cache-path structure is a mechanical property of Claude Code's plugin loader, not of which commit is checked out) but is explicitly not a GitHub-sourced install of the exact commits in this plan.
- The macOS `shasum -a 256` fallback (Assumption A3) is recorded as an accepted, undischarged gap rather than blocking the plan — no macOS hardware was available, and the plan's own Task 3 instructions anticipated and pre-approved this outcome.
