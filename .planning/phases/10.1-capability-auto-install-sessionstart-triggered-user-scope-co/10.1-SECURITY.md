# Phase 10.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Claude Code host process → hook script | The plugin's bash hook runs unattended, with the end user's privileges, on every session start. | Process spawn, filesystem read |
| Hook script → gsd-core CLI | The script supplies `--yes`, suppressing the interactive executable-surface disclosure a human would otherwise read. | CLI invocation, `--scope global --yes` |
| Plugin bundle files → user's global capability ledger | Bundle content under `$CLAUDE_PLUGIN_ROOT/.gsd/capabilities/<id>/` becomes active capability code after an unattended install. | Capability bundle content |
| Local filesystem (`$HOME/.gsd/`) → hook script | The sidecar hash file is read to decide whether to skip the install. | Hash sidecar file |
| Plugin distribution artifact → end user's machine | The release zip and the marketplace clone are two distinct content sets; whichever the user installs becomes the source the auto-install trusts. | Plugin bundle (two distribution channels) |
| Vendored script copy → authored original | Three separately-shipped copies of the same logic can silently diverge. | Script/bundle bytes |
| `ponytail-everywhere` SessionStart/SubagentStart hooks → gsd-core CLI | Same unattended-install boundary as Plan 01, reached from four registered hook matchers. | CLI invocation |
