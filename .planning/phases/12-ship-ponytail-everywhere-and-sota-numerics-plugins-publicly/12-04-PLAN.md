## Alternatives Considered

- **`git rm -r <dir>`**: removes the paths from the index and from the working tree in one command,
  leaving no untracked residue. `git rm --help` (git 2.55.0, verified this session, 2026).
- **`git rm -r --cached <dir>` plus a `.gitignore` entry**: untracks the paths while leaving the files
  on disk, so the repository stops shipping them but the developer keeps a local copy. Same doc-ref,
  `git rm --help` (git 2.55.0, 2026).
- **Leave both subdirectories tracked and rely on the marketplace entries alone to route installers
  to the new repos**: zero diff in this repository, and the two trees stay available as a local
  reference. This is what the phase looked like before the mid-discussion topology revision recorded
  in `.planning/phases/12-ship-ponytail-everywhere-and-sota-numerics-plugins-publicly/12-CONTEXT.md`
  (2026).

Decided by: simplicity/LOC. The three tie on performance, so the next ranked criterion decides, and
locked decision D-04 settles it independently: it requires that "no dual-copy authoring source" be
left behind. The `--cached` variant leaves exactly that copy on disk, and the do-nothing option
leaves two authoritative trees for the same plugin in two repositories — the drift hazard D-04 exists
to remove. The plain removal is both the mandated option and the shortest.
