<interfaces>
The public entry point remains:
- `bash plugins/beads-lifecycle/hooks/capability-auto-install.sh <capability-id>`

The gsd-core compatibility floor remains `>=1.10.0`; the actively verified/current runtime is public `@opengsd/gsd-core@1.12.0`. The hook may use only public CLI surfaces:
- `query skills-root --runtime <runtime>` with `--config-dir` only where supported
- `capability installed --json --runtime <runtime>`
- `capability install <capability-dir> --runtime <runtime>`
- `capability set <id> --runtime <runtime> --profile=full --yes`
- active installed CLI acceptance for selected commands and rejection of the retired command

Lock boundary:
- Before reading or mutating projection state, a small Python stdlib wrapper opens a plugin-owned regular lock file without following symlinks, acquires `fcntl.flock(fd, LOCK_EX | LOCK_NB)` exactly once, marks the descriptor inheritable, and `exec`s the same Bash hook in internal locked-child mode.
- The re-executed hook validates that the inherited descriptor and lock path identify the same regular file, then holds the descriptor throughout fast-path observation, native install/set, post-set verification, and receipt publication. The kernel releases it on exit or crash.
- `EACCES`/`EAGAIN` means one bounded busy diagnostic and successful fail-open exit. Unsafe lock targets or other helper failures produce one bounded fixed diagnostic and no projection. There is no polling, sleep, PID identity, quarantine, or stale-lock takeover path.

Ledger boundary:
- One plugin-owned projection-v2 file stores a global installed bundle generation and runtime rows containing both that generation and the observed post-native-set selected-surface fingerprint.
- A generation mismatch invalidates all rows before the active runtime is reconciled. The publisher rejects any existing nonregular canonical target, writes canonical state through `tempfile.NamedTemporaryFile` in the ledger directory, flushes and `fsync`s it, then atomically calls `os.replace` in that same directory. The temporary is cleaned on every failure.
- Legacy state is neither renamed nor removed before successful canonical replacement. After success, remove it only if it is a regular non-symlink plugin-owned file; canonical state remains authoritative if legacy cleanup fails.
- Runtime-native rewrites are valid. Production compares the installed generation and observed selected-surface fingerprint, not raw installed bytes and not an independently materialized transformed oracle.

Ownership boundary:
- Existing destinations are mutable only when the destination is a real directory and its marker is a real, non-symlink regular file whose exact content proves plugin ownership. A symlinked marker or same-name user-owned destination fails open before native install/set.
</interfaces>

<alternatives_considered>

| Rank | Mechanism | Performance | Simplicity / LOC | Ecosystem | Maintenance | Decision |
|---:|---|---|---|---|---|---|
| 1 | Python stdlib `fcntl.flock` wrapper plus `NamedTemporaryFile`/`os.replace` | One nonblocking syscall on the fast path; kernel releases locks without recovery work | Deletes custom PID/start-time/quarantine logic and reuses Python already required by the hook | Stable POSIX/Python primitives with primary documentation | No stale-owner format or recovery protocol to maintain | Selected |
| 2 | External `flock(1)` wrapper plus shell publication | Comparable locking cost | Short lock call, but secure structured publication and portability still need Python | Common on Linux, not guaranteed by the hook's declared environment | Adds an optional executable and split error semantics | Rejected |
| 3 | PID/process-start symlink token with stale quarantine | Extra procfs/`ps`, readlink, rename, and reacquire work | Highest LOC and most race-sensitive | Hand-rolled process identity across platforms | Requires permanent stale-owner and acquisition-window maintenance | Remove |
| 4 | Invoke native install/set on every SessionStart and keep no receipt | Repeated hashing, installation, and selection on every startup | Least persistent state | Uses only gsd-core | Avoids ledger maintenance but discards the required fast path and does not serialize cooperating hooks | Rejected |

Ranking priority is performance, then simplicity/lines of code, then ecosystem support, then maintenance overhead. Primary contracts: Python [`fcntl.flock`](https://docs.python.org/3/library/fcntl.html), [`NamedTemporaryFile`](https://docs.python.org/3/library/tempfile.html#tempfile.NamedTemporaryFile), and [`os.replace`](https://docs.python.org/3/library/os.html#os.replace); npm exact-version installation is documented by [`npm install`](https://docs.npmjs.com/cli/install/), and CI follows GitHub's [Node.js workflow guidance](https://docs.github.com/en/actions/tutorials/build-and-test-code/nodejs).
</alternatives_considered>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Concurrent hooks → shared state | Multiple SessionStart processes may observe or mutate installed generation, selected surface, and receipt state. |
| Filesystem → ownership and ledger | Lock, marker, destination, canonical ledger, legacy state, and temporary paths may be precreated as hostile object types. |
| Plugin → gsd-core | The hook delegates installed-capability transformation and selection to a separately installed public runtime. |
| Non-cooperating writer → transaction | A process that ignores the advisory lock can mutate installed or selected state around the final observation. |
| CI → npm/GitHub supply chain | A clean runner fetches the exact public runtime and official tagged source fixture. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-22-01 | Tampering | lock file | high | mitigate | Open without symlink following, require matching regular path/fd identity, acquire one nonblocking `flock`, inherit fd across exec, and let the kernel release ownership. |
| T-22-02 | Tampering | ownership marker | high | mitigate | Require a non-symlink regular marker with exact owner content before native mutation; spy that install/set remain unused otherwise. |
| T-22-03 | Tampering | ledger publication | high | mitigate | Reject nonregular target, use secure same-directory `NamedTemporaryFile`, flush/fsync, atomically `os.replace`, clean failures, and defer legacy cleanup until success. |
| T-22-04 | Denial of service | helper diagnostics/contention | medium | mitigate | Fail open after one lock attempt and emit one fixed bounded line without raw helper output, traceback, or uncontrolled path content. |
| T-22-05 | Tampering | direct external writer | medium | mitigate | Recheck installed generation and selected fingerprint immediately before publication; explicitly rely on next-start mismatch invalidation for a later non-cooperating race. |
| T-22-06 | Elevation of privilege | cross-runtime/user-owned paths | high | mitigate | Resolve only the active runtime's public skills root and never copy across roots, delete sibling capabilities, or mutate unowned same-name destinations. |
| T-22-SC | Tampering | CI npm/source provisioning | high | mitigate | Pin official package and tag to v1.12.0, verify runtime identity before tests, verify immutable v1.10.0 fixture SHA/package version, and add no new production dependency. |
