## Alternatives Considered

- **`git rm -r <path>` for each bundle, paired in one commit with the two `.gitignore` un-ignore-line
  deletions and the `.gsd-capabilities.json` reconciliation**: removes the paths from the index and
  the working tree in one command each and leaves no untracked residue or dangling ignore negation.
  `git rm --help` (git 2.55.0, verified on this machine, 2026). This is the exact three-part shape
  commit `4d83504` (2026-08-18) used for the two previously extracted plugins.
- **`git rm -r --cached <path>` plus leaving the files on disk**: untracks the paths so the repository
  stops shipping them while the developer keeps a local copy. Same doc-ref, `git rm --help` (git
  2.55.0, 2026). Rejected in the recommendation because it leaves precisely the hand-editable,
  now-unversioned second copy the duplication concern is about.
- **Leave both bundles tracked and rely on the marketplace entries alone**: zero diff, and the two
  trees stay available as a local authoring reference. This is what 15-CONTEXT.md's D-00 states
  verbatim (2026), and it is a live option rather than a straw man — which is why this plan routes the
  choice through a blocking checkpoint instead of deciding it unilaterally.

Decided by: maintenance overhead. All three are one-shot operations of identical cost, so
performance, size, and ecosystem support all tie; what separates them is what each leaves behind for
the next editor. Two of the three leave a second authoring copy of a plugin whose canonical home is
now an external repository — the drift hazard commit `4d83504` (2026) removed once already for the
sibling plugins, and the condition under which one of those copies was found masking a
resolution bug. The operator decides, and the checkpoint names that asymmetry explicitly rather than
burying it.
